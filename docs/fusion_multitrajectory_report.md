# LiDAR＋视觉融合：多轨迹与图像干扰测试

测试日期：2026-09-16。运行目录：`/home/yanfa/P3/lidar_visual_fusion`。

## 结论

本轮使用 VoxelMap＋XFeat/LighterGlue，不增加新模型或后台服务。融合改用视觉帧间运动，LiDAR 保留三维位姿和完整方向协方差。视觉失效时停止视觉约束；视觉重启后，局部运动不需要拼接旧的视觉坐标原点。

另外修正了仿真点云外参中的坐标轴约定：点云发布端已经转为 ROS FLU，继承的外参又保留了另一套传感器轴。修正依据是发布端源码和首帧地面位置，不是按参考轨迹拟合。旧坐标版本的实验保留作诊断，不作为当前融合演示结论。

## 耗时与内存

均以 1 倍速重放。LiDAR、视觉列为各自处理耗时中位数；位姿列为从回放器开始发送该组传感器数据，到最后一次同时间戳可靠位姿抵达检查器的中位数。它不包含未知的相机曝光到录包延迟。

| 路线 | LiDAR 中位数 | 视觉中位数 | 最后一次同帧位姿中位数 | 峰值 RSS（含 RViz） |
|---|---:|---:|---:|---:|
| 原修复段／正常光照 | 112 ms | 259 ms | 494 ms | 2.87 GiB |
| short／低对比度 | 88 ms | 227 ms | 464 ms | 2.75 GiB |
| 次日／平坦路线 | 84 ms | 260 ms | 462 ms | 2.89 GiB |
| 后续起伏段 | 113 ms | 266 ms | 492 ms | 2.95 GiB |
| 原修复段／图像干扰 | 113 ms | 258 ms | 490 ms | 3.13 GiB |

原始 bag 约每 3～4 秒才有一组完整输入，这不是算法每帧需要 3～4 秒。上述数据也不证明整条链路已经通过高频实车压力测试。

内存按进程树 RSS 统计，包含 P3 的 RViz 和显示进程，可能重复计算共享页。地图以分块 SQLite 保存到磁盘；常驻瓦片、点云预览、图像队列和位姿历史都有上限。全局高分辨率栅格超出上限时，局部高程图、全局概览、增量地图和分区查询继续工作；全局 NPZ 不能替代最新的 SQLite 地图。

## 实现与检查

- **方向性不确定性**：LiDAR 的弱方向降低权重，配准失败仍拒绝。不会因为地面某个方向弱，就把整帧 LiDAR 全部丢弃。
- **视觉接入**：在已有节点内，将同一视觉 epoch 的两帧位姿转换为车体运动。速度协方差由位姿协方差经过相对运动变换得到，并包含时间间隔平方项。保留工程噪声下限和创新门限；这些不是实测校准后的概率保证。
- **恢复与异常**：黑屏、过曝、图像失效、几何失败、超时、非单调时间戳和位姿跳变都能关闭视觉。新 epoch 不会产生跨原点的巨大速度。单纯的中等置信度波动通过协方差降权，避免反复重新启用等待。
- **显示与发布**：沿用 P3 的 RViz 窗口和消息定义。正式里程计、TF、轨迹、高程图、点云图和增量地图都有检查记录；保存后检查队列清空和扫描计数。
- **资源**：无需常驻第二张视觉地图或新深度网络。高程瓦片最多 64 块，瓦片缓存预算 128 MiB，点云预览最多 15 万点，RViz 继续使用 P3 的约 5 万点显示上限。
- **IMU**：保留可选自动接入与无 IMU 回退。本轮所有 bag 都没有 IMU，不能据此报告加 IMU 后的精度提升。

多轨迹表对应每个结果目录保存的冻结版本。最终交付在该版本上追加了地图背压和按实际到达周期判断失联的处理，随后重新编译、核对安装代码，并做针对性 ROS 回归和短段完整回放；没有用新增的回归用例重新计算或覆盖上表。
