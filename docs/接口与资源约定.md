# 接口与资源约定

参考原项目 `workspace/课题三Odometry位姿接口说明.md`、`workspace/docs/map_delivery_interfaces.md`、`workspace/课题三ROS2输入接口联调说明.md`，以及用户桌面的《方案.md》《集成演示要求.md》。

## 坐标、时间与命名

- TF：`map → odom → base_link`。本后端没有回环地图修正，`map → odom` 为恒等静态变换，EKF 是 `odom → base_link` 的唯一发布者。
- 发布的是经外参转换的车体位姿，不是把相机/IMU坐标系改名。输入外参同时用于几何点云、VoxelMap/视觉里程计和传感器静态 TF。
- Odometry：`header.frame_id=odom`，`child_frame_id=base_link`。长度单位 m，角速度 rad/s，四元数 x/y/z/w。融合速度由 EKF 输出，表达于车体；协方差使用有限下限，不能将全零上游协方差视为零误差。
- 时间戳采用传感器时间；在线接收使用原驱动的 `meta_relative` 同批对齐模式。历史损坏时间戳修复是独立显式参数。
- 原项目正式位姿与演示位姿发布同一消息；不启用已废弃的 `/Car/T3/semantic/current_pose`。
- 地图消息 Reliable / Transient Local / KeepLast 1；图像/点云输入可靠性可配置，short bag 使用 Reliable 和有界队列。接原始驱动前核对 QoS 兼容性。
- 原始输入：左右目 `/Car/T5/Cam_Left/image_raw/color`、`/Car/T5/Cam_Right/image_raw/color`，点云 `/Car/T5/OS1/points`；语义可选 `/task2/seg_mask`。
- 当前与 P3 一致的 `grid_map_msgs/msg/GridMap` 的时间与坐标字段位于顶层 `header`；本目录消息定义和 ROS 实测均已核对。

## 地图与规划接口

| 接口 | 类型 | 坐标与含义 |
|---|---|---|
| /Car/T3/localization/odometry；/T3/semantic/current_pose | nav_msgs/msg/Odometry | odom / base_link |
| /Car/T3/debug/trajectory；/T3/semantic/trajectory | nav_msgs/msg/Path | map；显示最近最多 5000 个轨迹点 |
| /Car/T3/mapping/grid_map；/T3/mapping/grid_map；/T3/mapping/elevation_map | grid_map_msgs/msg/GridMap | odom；64×64 m，0.2 m/格，320×320 |
| /T3/mapping/lidar_map | sensor_msgs/msg/PointCloud2 | map；累积地图的有界三维预览 |
| /T3/mapping/elevation_cloud | sensor_msgs/msg/PointCloud2 | map；每个有效高程格对应点阵 |
| /T3/mapping/traversability | nav_msgs/msg/OccupancyGrid | map；0～100 通行代价，-1 未知 |
| /T3/semantic/incremental_map | t3_interfaces/msg/IncrementalSemanticMap | map；当前完整滑动窗口，收到后替换窗口 |
| /Car/T3/mapping/global_grid_map | grid_map_msgs/msg/GridMap | map；全范围、原分辨率，elevation 层 |
| /Car/T3/mapping/global_overview | nav_msgs/msg/OccupancyGrid | map；全局低分辨率几何总览 |
| /Car/T3/mapping/global_map_revision | std_msgs/msg/UInt64 | 紧凑 SQLite 已提交的版本号 |
| /Car/T3/mapping/get_grid_map | grid_map_msgs/srv/GetGridMap | map / odom 中心位置、长宽、所需层 |
| /Car/T3/mapping/save_grid_map | std_srvs/srv/Trigger | 完成数据库检查点后返回 |

global_grid_map、global_overview、global_map_revision、get_grid_map、save_grid_map 同时提供对应的 `/T3/mapping/...` 别名；`/T3/mapping/save` 也可触发保存。

局部图默认 2 秒发布一次有效更新。完整全局图和总览默认最多每 20 秒发布一次；中间版本合并以控制计算和序列化成本。原项目完整全局消息的几何含义与分辨率保持不变。

局部 GridMap 层包含 elevation、elevation_variance、occupancy、semantic_id、semantic_confidence、observation_count、height_range、roughness、color，以及新增 slope、step、traversability。GridMap 使用原项目的 grid_map 数组顺序；自定义增量消息和 OccupancyGrid 为 [row=Y, col=X] 行优先。

通行代价取坡度、相邻高差和单格高度范围；坡度上限默认 35°，高差默认 0.3 m。不具备有效邻域证据的位置保持未知。未实现车体轮廓膨胀和动态障碍预测，规划端需按自己的车体尺寸处理这些步骤。

全局总览固定最多 256×256 格，初始 1 m/格；区域增长时按 2 倍降低分辨率并保留已观测范围。它用于全局展示和粗粒度态势，精细通行判断使用局部图或查询结果。

### 单条完整全局消息超限

完整全局图默认最多 1,000,000 格；超限或内存压力下：
1. 全量高程和点云继续分块保存在磁盘。
2. 完整全局话题发布空 GridMap，并令 `global_grid_available=false`。
3. 不将裁剪的窗口或降分辨率图伪装成完整全局图。
4. 规划端使用局部图和区域查询；总览继续按自己的分辨率发布。
5. 历史 dense NPZ 可能仍是前一版本，读取时核对版本号和状态。

区域查询默认最多 250,000 格，内存压力时最多 160,000 格。无效坐标、过大请求和未知层返回空 GridMap并记录原因；标准服务没有 success 字段，调用者检查 layers/data 非空。

```bash
ros2 service call /Car/T3/mapping/get_grid_map grid_map_msgs/srv/GetGridMap \
 '{frame_id: map, position_x: 0.0, position_y: 0.0, length_x: 30.0, length_y: 30.0, layers: [elevation, occupancy, traversability]}'
```

## 磁盘规范

运行输出在本独立目录的 `results/run_时间` 下，遵循原项目“对外交付文件放根目录，内部状态放 _internal”的约定。

| 文件 | 作用 |
|---|---|
| trajectory_map.tum | 完整融合车体轨迹，持续流式写入 |
| global_grid_map.sqlite3 | 原项目紧凑地图格式；相同编码器，版本事务提交 |
| global_grid_map.npz | 容量允许时的完整矩阵，采用原项目保存函数 |
| lidar_map.pcd | 停止后流式导出的三维地图 |
| local_elevation_latest.npz | 最近局部高程、方差、坡度、台阶和通行率 |
| map_metadata.json | 本次配置、内部数据库路径、末次位姿与时间 |
| map_statistics.json | 地图缓存、版本、丢帧、存储与压力状态 |
| resources_latest.json / resources.jsonl | 本任务进程树 RSS、系统可用内存和磁盘 |
| _internal/elevation_tiles.sqlite | 无损单元状态，每个地图块一个压缩载荷 |
| _internal/lidar_voxels.sqlite | 全量 3D 体素索引 |
| _internal/grid_map_snapshot/map_index.yaml | 停止后导出；可由原项目加载器读取 |

紧凑库沿用厘米高程与原质量层定点编码；无损库保留原浮点状态。默认块大小 128×128，消费者读取 metadata.tile_cells，不硬编码 256。语义/占据没有实际观测的位置在文件里继续保持未知；在线几何通行代价通过相应 ROS 层提供。

保存成功表示检查点落盘，不表示全量 PCD 已导出。完整导出在停止后执行，避免长时间读取快照阻止 WAL 回收；导出前检查预计临时文件所需空间。

## 内存预算：配置上限，不是实测结果

| 项目 | 默认约束 |
|---|---|
| 常驻高程块 | 最多 64 块，且数组不超过 128 MiB；当前 5 类/128² 格时约 61 MiB 数组 |
| 内存压力下高程块 | 最多 16 块；逐块保存后淘汰 |
| SQLite 页缓存 | 三个活跃数据库各 16 MiB；关闭 mmap，临时数据优先文件 |
| LiDAR显示 | 最多 150,000 个点；0.3 m 预览体素＋确定性抽样 |
| 精细点云 | 0.12 m 三维体素，落盘去重；不把完整地图读回内存 |
| 待配准点云 | 最多 4 帧；单消息字节数与点数有上限 |
| 左右图同步 | 每侧 2 张已缩小 mono8 图，约 2.1 MiB 同步缓存 |
| 原始图像 | 2448×2048 校验，DDS 订阅 depth 1；不缓存多张原始 BGRA 大图 |
| 位姿缓存 | 最多 1200 个样本 |
| 轨迹显示 | 最多 5000 点，完整轨迹写文件 |
| VINS | 单线程图像处理；双目队列 2、特征队列 4、IMU队列 4000 |
| VoxelMap | 局部半径 80 m，最多 10000 根体素；可选 IMU 缓存 4000 样本 |
| 节点日志 | 每文件约 16 MiB 轮换，保留 3 份归档；不删除地图和原始数据 |

VoxelMap 的空间范围和根体素数限制不等于严格的内存字节上限。RSS 包含解释器、原生库、DDS、临时数组与 RViz；上表不能相加后当成整机峰值保证。

地图节点 RSS 超过 1536 MiB 或系统可用内存低于 2048 MiB 时，缩小块缓存、减少点云显示量、降低地图发布频率，并暂停大幅全局消息。

资源监控每 5 秒采样本任务记录进程及其子进程。总 RSS 超过 6144 MiB 记录告警；超过 8192 MiB、系统可用内存低于 512 MiB 或磁盘不足 1 GiB 持续三次时，停止本任务的采集、回放、RViz和管线。此为软件采样保护，有反应延迟，不是操作系统硬限额。

磁盘低于 5 GiB 时暂停新增建图并报告 map_writable=false，保留已写地图；不会自动删除历史地图。定位可继续输出，规划端必须同时检查地图时间戳与状态，避免使用过期地图。

## 当前视觉融合内部消息

当前默认 `visual_constraint_mode: body_twist`。内部 `/fusion/vision_odom_guarded` 仍用 `nav_msgs/msg/Odometry`，EKF 仅使用其 `twist` 的六个车体运动分量及协方差，`child_frame_id` 为 `base_link`。`pose` 保留视觉自身的 `learned_epoch_N` 坐标和大协方差，不参与 EKF；不能把这条内部消息的 pose 当作正式全局位姿。

正式 `/T3/semantic/current_pose`、增量地图和 TF 的坐标与消息契约不变。光照或几何失效、重置、过期时关闭视觉约束，恢复后只计算同一 epoch 内的运动。细节和验证见 [最终多轨迹报告](fusion_multitrajectory_report.md)。
