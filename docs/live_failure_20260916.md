# 现场连续配准失败记录（2026-09-16）

来源：远程 `results/run_20260916_160110/`，16:01 启动的旧版本在线任务。以下故障快照在重启前取得。后续代码改动和验证见 [视觉接续与子图恢复](visual_recovery_20260916.md)。

## 已观察到的事实

- 第 620 帧起出现持续 LiDAR 配准失败；检查快照到第 1172 帧时已连续 **553 帧**失败。
- LiDAR 仍收到约 6.35 万点，降采样后约 1.33 万点；每帧运行到 20 次迭代上限，`solver_converged=false`、`solution_stable=false`。当前场景仍有大量匹配，但更新未达到收敛条件。
- 无标定 IMU 时，现有保护将失败位姿回退至最后可信位姿，冻结配准地图更新；持续失败期间位置保持约 `[-21.21, -23.73, -0.01]` 米。
- 视觉没有完全失效：最近 200 次处理中 196 次为 `tracked`，另有 2 次数据过期、2 次重新初始化；近期单帧约 0.25 秒，部分帧 PnP 内点率约 99%。这只能说明视觉前端匹配通过，不能据此推出全局定位准确。
- 融合状态出现 `visual_primary` 且 `vision_enabled=true`，但 `localization_valid=false`。一份快照的位置最大方差约 **956 m²**，超过正式位姿输出上限 **4 m²**；同时也有视觉超时和重新恢复阶段。
- 正式位姿停发，地图停在第 406 次更新。不能把旧地图还显示在窗口中理解为系统仍在正常定位建图。

## 代码层面的解释

故障版本的视觉以车体运动增量/速度约束进入滤波器。它能在合格时继续提供运动信息，但不能在长期失配或观测中断后直接消除已累积的全局位置、方向不确定性。最终输出保护仍会拒绝不合格结果。

旧版本 LiDAR 的回退保护避免了连续失败时无约束外推，但缺少持续失配后的子图恢复；每次仍从旧可信状态尝试旧局部图，车辆离开后可能无法回到收敛范围。首次持续失配前，输入间隔约 1.27～1.46 秒，估计速度约 0.12～0.30 m/s；当前证据不能把首次失败简单归因于根体素太小、速度太快或网络问题。

## 后续处理

该段定位无效时应停车，不继续使用它执行导航。仅提高迭代次数、放大可接受方差或直接清空地图原点，不能保证可靠恢复。

现已增加独立视觉接续、视觉初值和多帧确认后的子图恢复；候选子图失败时合格视觉与建图继续，保存原地图坐标关系及其不确定性。独立测试和真实节点完整链路验证通过，实际行驶精度仍待新轨迹验收。
