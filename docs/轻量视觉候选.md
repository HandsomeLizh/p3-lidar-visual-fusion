# 轻量视觉实现与启动

## 当前状态

XFeat＋LighterGlue 的双目里程计、LiDAR 融合接入口和启动脚本已实现。XFeat＋双向最近邻、SuperPoint＋LightGlue、ALIKED＋LightGlue 使用同一几何与融合实现，作为对照分支。作者源码、模型权重和私有依赖已准备；XFeat＋LighterGlue 已在 Orin CUDA 上运行完整 short bag。独立视觉约 0.099 m RMSE、稳定处理时间中位数 225.7 ms，但旧融合没有有效接纳视觉，最终误差 2.57 m。见 [基线报告](short_bag_test_20260915.md)。其他模型及真实极端光照尚未完成同条件对比。

本轮目标是：一，降低处理延迟与资源占用；二，极端光照下整套定位建图仍可运行。视觉不可用时停止视觉观测，由 LiDAR 继续定位和建图。不能据此宣称轻量匹配器在极端光照下比 RoMa 更准确。

## 推荐启动入口

在远程执行：

```bash
cd /home/yanfa/P3/lidar_visual_fusion

# 已有传感器发布者时，使用同一 ROS domain。
./start_xfeat_fusion.sh --domain 57 --rviz

# 需要本目录启动 Env_X 接收器时：
./start_xfeat_fusion.sh --domain 57 --capture --rviz

# 历史 bag；正常时间戳无需缩放。
./start_xfeat_fusion.sh --bag /path/to/bag --domain 57 --rviz
```

旧包 20260824_235238 的异常时间单位需要显式追加 --header-time-scale 1000000；不要对其他包默认添加。这里的 57 是隔离演示域，接规划端时按原项目的实际 domain 设置，并在跨机器 DDS 通信时追加 --network。原项目正式位姿话题只能存在一个主发布者。

start.sh 的默认配置仍保留原方案 VINS 分支；本轮首选入口是 start_xfeat_fusion.sh。


每次运行只选择一个分支，先用 stop.sh 停止本目录上一轮。所有入口都可追加 --bag、--domain、--capture 等参数；学习式分支可用 --visual-device cpu 显式选 CPU。CPU 实时能力也必须实测。外部 RoMa 模式仍需要原程序独立发布 /fusion/roma_raw。

只有启动当前选中模型时才分配其运行内存，其余模型只是磁盘文件。每次运行将配置冻结到 results/run_*/profile.yaml，避免运行过程中修改公共配置改变已有任务。

## 实际计算链路

1. 复用项目双目外参与内参；输入缩放到 640×536 灰度图，并同步缩放内参。
2. 进行双目校正；学习模型提取最多 1024 个特征点。
3. 左右目匹配经过极线、视差、正深度及重投影检查后，三角化为稀疏三维点。
4. 缓存一个参考关键帧的特征和三维点，进行时序匹配、PnP RANSAC 和重投影优化。
5. 检查内点数量/比例/覆盖范围，以及当前双目三维点对估计运动的支持程度。
6. 输出带采集时间戳的 base_link 位姿；融合侧再检查图像质量、时间年龄、运动连续性与 LiDAR 增量一致性。

双目三维点用于视觉位姿估计。高程地图和累积点云继续由 LiDAR/已配置的 ToF 数据生成。本实现是有界关键帧双目里程计，没有添加视觉全局回环或长期视觉地图。

## 速度与占用控制

- 一份选中模型；当前图像对加一个参考关键帧。
- ROS 图像接收深度 1，每侧同步缓存 2 帧，等待推理的图像对最多 1 对。
- 默认视觉处理上限 5 Hz，使用最新待处理图像，避免排队越来越长。这是可配置上限，不是实测达到的频率。
- 严重黑屏/过曝先经过图像检查，不进入神经网络推理。
- 连续失败 3 次后以约 1 秒间隔探测恢复；LiDAR 不等待视觉。
- 仿真学习式视觉默认年龄上限 1.5 秒，采集时间年龄与实际等待都受限；进入融合前再次检查。
- 单独统计预处理、提取、左右目匹配、时序匹配、几何求解和端到端年龄。
- 默认不开启混合精度；可配置启用，需另行验证算子兼容性与误差。
- 资源监视覆盖本任务实际进程树。达到软阈值时优先停止本任务视觉进程；持续严重内存/磁盘不足仍执行原有整任务保护。

以上尺寸、点数、频率和阈值均为初始配置，尚未通过现场性能标定。

## 极端光照与故障退出

- 正常灰度/黑白输入可以使用；不会因为没有颜色而拒绝。
- 整幅黑屏、严重过曝、不可用图像、异常匹配、跳变或过期位姿不进入融合。
- 坏图像会关闭视觉门控，清理待融合视觉队列，并禁止更早的视觉结果重新启用门控。
- 图像恢复后，需要重新积累 LiDAR 一致性证据，再经过连续 4 帧恢复检查。
- 视觉重建参考段使用新的 learned_epoch_* 坐标系标签；融合侧重置该段历史，防止参考原点改变形成速度尖峰。
- 神经网络加载失败、视觉进程退出或资源停用不会触发 LiDAR/融合/地图进程退出。主链路启动不等待神经网络加载。
- 一般图像退化可自动探测恢复；视觉进程崩溃或因资源被停止后不自动反复重启，需显式重新启动任务。
- /fusion/status 的 operating_mode 指示 lidar_visual、lidar_only 或 waiting_for_lidar。

上述为旧 LiDAR 优先策略。新自适应配置不要求退化 LiDAR 为视觉背书；切换与失效已有合成 ROS 回归，真实异常光照仍需验证。详见 [候选与切换说明](candidate_status.md)。LiDAR 本身也需要有效点云和足够几何约束。

## 输出与诊断

原接口保留，包括：
- /Car/T3/localization/odometry 与 /T3/semantic/current_pose；
- /T3/semantic/incremental_map、/T3/mapping/elevation_map；
- /T3/mapping/lidar_map、轨迹、TF 和栅格查询服务。

新增内部接口：
- /fusion/learned_raw：未融合车体位姿，独立视觉参考段，无 TF；
- /fusion/learned_status：特征/几何/时间/资源统计；
- /fusion/status：融合模式、视觉拒绝原因及融合输出年龄。

运行目录写入 learned_metrics.json、最多 3×8 MiB 的 learned_metrics.jsonl 日志、fusion_status.json、resources_latest.json。时间分位数窗口最多 256 个已处理样本，同时保留累计输入/替换/拒绝计数，避免只看成功帧。

```bash
python3 scripts/summarize_learned_runs.py results/run_A results/run_B --output results/visual_comparison.json
```

## 待测试顺序

1. 运行 scripts/run_deferred_checks.sh，检查几何、位姿时序、存储与既有 ROS 故障回归。
2. 在真实图像对上运行 scripts/benchmark_learned_matcher.py，验证权重加载、CPU/CUDA 算子和显存。重复静态图像仅用于模型运行验证，不代表实时里程计速度。

4. 在仿真中实际施加黑屏、过曝、斜向强光、灰度和重复纹理，测连续性、错误匹配、恢复、地图重影。
5. 只终止本目录自己的视觉 PID，确认 LiDAR 位姿及非空地图继续更新；再以低资源阈值验证视觉优先停用。
6. 接规划端核对现有接口、TF、时间戳、QoS，并进行长时间内存测试。
