本次检查的是 P3 最新源码，当前长轨迹实验继续使用其启动时冻结的地图实现。以下为下一步改图的具体依据，不表示新方差融合已经接入当前运行。

## 已确认的最新实现

- `elevation_fusion.py` 定义 `ElevationFusionConfig`，可选 `mean` 与 `variance`。类默认仍为 `mean`；是否启用方差模式取决于实际参数。
- `semantic_grid.py` 新增 `elevation_fused_mean` 与 `elevation_estimate_variance`。方差模式按观测噪声加权更新高度，并设置最小方差与过程噪声。
- 同一扫描、同一格的点视作相关观测；不通过堆点数让置信度无限提高。
- 高度创新超过门限时拒绝该批观测，拒绝的数据不改变高度、置信度、计数或地表起伏统计。
- `tiled_semantic_map.py` 方差模式使用 v2 无损快照，并保存两份新增状态；均值模式保留 v1。加载时校验模式，避免恢复后丢失估计器状态。

默认 LiDAR 测量方差 0.01 m²、过程方差 0.0001 m²、最小方差 0.0004 m²、3σ 与最小 0.30 m 门限，是工程设置；源码明确未声称是标定过的传感器模型。

## 输出含义必须分开

现有 `elevation_variance_layer()` 仍用采样 M2/(n−1) 表示格内高度离散程度，`roughness` 取其平方根。这是地表起伏与观测散布，不是“融合高度的估计误差”。

新的 `elevation_estimate_variance` 是另一个状态。当前通用 GridMap 消息转换器可发布任意层，但现有高程方差接口没有自动变成该估计误差。接规划端时应新增有明确含义的层，而不是替换旧字段含义。

建议同一 GridMap 保留：

| 层 | 含义 |
|---|---|
| `elevation` | 融合后的高度 |
| `elevation_variance` / `roughness` | 原项目定义的高度散布 / 起伏 |
| `elevation_estimate_variance` | 融合高度估计的方差，单位 m² |
| `observation_count` | 观测计数，不能单独当成可信度 |
| 观测时间或新鲜度层 | 区分刚更新与较久未观察的位置 |

无效估计使用未知值；不将未知填成 0 方差。规划端结合估计不确定性与地形代价判断，而不是仅靠“地图看起来平滑”。

## 本目录需要补齐的接入位置

1. 将最新方差融合逻辑冻结到本目录，保留原项目文件和接口约定。
2. `DiskElevationMap` 当前只序列化旧 `_SNAPSHOT_TILE_FIELDS`；接入时必须同时扩展 SQLite schema、内存字节核算、淘汰/加载和导出字段，不能只复制 `semantic_grid.py`。
3. 当前地图节点只缓存位姿矩阵，丢弃输入 Odometry 的协方差。后续将定位不确定性与雷达测距噪声传播到高程观测，再交给每格方差融合。
4. 位姿协方差需使用与发布消息一致的坐标与姿态扰动定义；不能把平移和转角方差直接相加。较远点对姿态误差更敏感。
5. 定位结果高度相关，同一扫描的大量点也相关；延续 P3 的每批有限信息量约束，避免重复访问把置信度压得过低。
6. 新估计方差层、区域查询、保存/恢复与 RViz 显示一起接通；地表真实台阶不能仅因为相邻格差异大就被平滑掉。

## 内存增量估算

两个 float32 状态在 64 个 128×128 常驻块中增加约 **8 MiB 数组**；新增一个 320×320 float32 发布层约 **0.39 MiB**。缓存 1200 份完整 6×6 float64 位姿协方差约 **0.33 MiB 数组**。

这些是数组估算，不包含 DDS 副本、序列化、Python 对象和工作缓冲区；仍需按完整进程树测峰值，并让块缓存按新字段的实际字节数淘汰。
