# 仿真速度＋角速度：坐标、积分误差与使用条件

2026-09-17 晚间补充：已核验两段最新遥测及四段历史记录。**当前线速度未通过位移积分验证；航向角速度仅适合继续做短时辅助试验，尚未启用融合。** 具体数值、metadata 与 6668 的区别及复验命令见本文后半部分。当前 capture 保持原运行版本，按用户要求暂不切换。

本补充采用用户最新说明：**输入是仿真的线速度＋角速度，原始轴 X 向后、Y 向下、Z 向左；不是实车加速度计＋陀螺仪。**

## 可用性结论

**这类输入可以做速度辅助，也可以积分成 SE(3) 位姿增量；没有加速度不会阻止这两种用途。** 缺少加速度只意味着不能直接按完整六轴惯导模型做 IMU 预积分。

机体线速度 v 和角速度 ω 已知时，传播关系是 `位置变化率=当前旋转×v`、`旋转变化率=当前旋转×[ω]×`。它需要明确坐标、单位和采样时间；加速度不是必需输入。应从定位器当前局部状态开始传播，不需要注入 UE 绝对位置或姿态。

**当前暂不直接启用的原因是实际输入与位姿变化的残差及时间语义还没闭合，不是因为它缺少加速度。** 仿真运动反馈应保持独立速度接口；未来实车标准 sensor_msgs/Imu 接口继续保留。

## 换轴数学已核对：现有 C 正是用户约定

原始线速度到 ROS FLU（前、左、上）：

```text
B = [[-1, 0, 0],
     [ 0, 0, 1],
     [ 0,-1, 0]],   det(B)=-1

v_FLU = B v_raw = (-vx_raw, vz_raw, -vy_raw)
```

如果原始角速度遵循对应的轴向量正转约定，则：

```text
w_FLU = det(B) B w_raw = (wx_raw, -wz_raw, wy_raw)
```

旧 P4 接收器已经做了：

```text
v_decoded = D_v v_raw,  D_v = diag(1,-1,1)
w_decoded = D_w w_raw,  D_w = diag(-1,1,-1)
```

因为两个 D 都等于自身逆矩阵，叠加后的换轴分别为：

```text
B D_v = det(B) B D_w = C

C = [[-1,0,0],
     [ 0,0,1],
     [ 0,1,0]],   det(C)=+1
```

所以，对**已被旧驱动解码的 /car/telemetry 或 /car/odom**，线速度与角速度都乘同一个 C 是正确的。本次诊断已经这样计算。**不需要再额外翻一次 Y；原始线速和原始角速不能不加区分地使用同一个 B。**

用户声明确定了原始轴名称；角速度是否严格采用上述轴向量正转定义，仍需发送端实现或实际转向数据核验。本轮 yaw 数据支持该轴/符号，但未充分验证 roll、pitch 两轴。

注意：直接读 metadata 原始字段时，应先确认它是否与车辆协议同一套原始数据。若确认，才对原始线速用 B、原始角速用 det(B)B；不能把仅适用于旧解码结果的 C 再套到原始 metadata。

14 个参考转角超过 1° 的一秒窗口，在用户轴约定对应的 C 下：

- 解码 wy 对参考机体 yaw 相关系数 0.9834，符号一致 14/14。
- 按 deg/s 转为 rad/s 后，一秒三维姿态误差中位 0.790°。

### 先前平移段（20:02:27 起约 12 秒）

同一个 C 下，9 个运动窗口的线速度方向误差中位 49.085°；反馈速度/位置差分速度比中位 2.748，线速残差中位 0.21201 m/s。

## 最小可用条件

1. **字段绑定和换轴：** 确认当前入口是原始 metadata 还是旧驱动解码消息，按上述对应矩阵；确认角速度正转定义。
2. **单位：** 线速明确为 m/s；角速明确度/秒还是 rad/s，并且仅转换一次。车辆协议旋转段证据不能直接当作 metadata 单位声明。
3. **时间：** 用与速度定义一致的源采样时刻；如果速度按仿真时间定义，不能未经核对就用接收墙钟积分。metadata 有 batch timestamp，但每个角速与该时刻的绑定、elapsed_seconds 语义仍未确认；车辆 21 float 协议只有接收时间。
4. **误差与门控：** 通过以上条件后，可将 v、ω 放入独立 TwistWithCovarianceStamped 辅助，或做短时 SE(3) 传播，保留新鲜度、异常值、协方差和断流回退。尚未闭合的方向/尺度残差不能隐藏在小协方差里。

当前 metadata 历史原件有 velocity、angular_velocity、timestamp，没有 acceleration；因此应按仿真运动反馈评估，而非完整实车 IMU。无需伪造加速度，也无需更改实车接口。

本次没有启用辅助、修改运行配置、控制车辆或增加长期采样。原始数据和量化结果仍在同目录的 metadata_field_audit、telemetry_consistency_30s 与 gyro_yaw_crosscheck JSON。换轴数值验证见 coordinate_transform_verification_20260917.json。

## 位移到底差多少

以下是 **6668 车辆遥测速度的离线积分诊断**，不是当前视觉＋LiDAR 定位器的 ATE，也不是 metadata 的实测结果。位置反馈仅作评分；自由积分只用开始时的参考姿态对齐，之后不读取参考位姿，没有事后轨迹对齐或比例拟合。按候选机体系、m/s、deg/s 和接收单调时钟计算。

| 连续记录 | 参考净位移 | 速度自由积分的净位移 | 终点位置误差 |
|---|---:|---:|---:|
| 最新平移段，12.02 秒 | 0.858 m | 2.249 m | **1.803 m** |
| 最新主要原地转弯段，30.03 秒 | 0.0328 m | 0.1837 m | **0.2065 m** |

终点误差是两个位移向量的距离，不能只减长度。12 秒段参考位移为 `(0.780, -0.356, 0.034)` m，积分位移为 `(2.047, 0.885, -0.291)` m，方向和大小均不一致。

为隔离角速度误差，又用每帧参考姿态旋转线速度再积分，终点仍差 **1.805 m**。这说明平移问题不能主要归因于陀螺积分转歪；线速度表达坐标、取值对象和时间基仍需核对。不能仅改一个符号，或把最新一段乘约 0.35 就启用。

四段历史记录使用相同固定变换、单位和规则复验。此前已观察到：按声明的机体系换轴后，速度方向随车辆航向约呈负两倍变化。按这个关系作**仅诊断的补偿**，部分记录方向会改善，但速度尺度仍跨记录不一致。这个补偿使用评分姿态，不是可部署的独立定位方法，未加入任何运行代码。

## 时间核对发现了什么

- 两段新记录中，驱动 ROS header 到审计订阅端的延迟中位均约 **1.1～1.2 ms**。这只能说明驱动之后的本机转发快，不能测出 UE 到驱动前的等待，也不能证明物理采样新鲜。
- 12 秒记录的接收间隔最小约 **0.53 ms**、最大约 **216 ms**；存在毫米级位置更新在约一毫秒内挤在一起到达的现象。不能把这些接收差分产生的瞬时“高速”认定为真实运动或跳变。
- 6668 现有报文没有源采样时间和序号。重复字段可能是新鲜但不变的值，也可能是旧状态重复发送；单靠 ROS 接收时间无法区分。
- **metadata 有 timestamp**，但目前只留有 9 月 16 日的一批原件；不能用一个样本计算位移误差。其 `elapsed_seconds` 的生成含义未知，不作为积分步长。
- 已查 216 保存的 P3/P4 代码和小文档，未找到实际 UE 速度取值函数、metadata 生成函数、Vortex physics 步长或时钟倍率。未访问 104。不能断言是网络慢、仿真慢或者固定单位倍率中的哪一个。

## 怎么用才合理

### 当前能确定的范围

| 输入 | 当前结论 | 可采用的用途与限制 |
|---|---|---|
| 三轴线速度 | 尚未通过跨记录位移核验 | 保持诊断用途，暂不接入 XYZ 位置传播 |
| 航向角速度 | 6668 的原始/解码 Y 分量与转向符号较一致，数值更接近 deg/s | 可继续试验短时转向初值；不能作为长期航向真值 |
| 滚转、俯仰角速度 | 运动激励与正转符号证据不足 | 不能因 yaw 通过就把三轴全部启用 |
| 低速度、低角速度 | 有静止辅助价值 | 必须结合图像或 LiDAR 静止证据；不能单独把位姿锁住，更不能把重复旧报文当新证据 |
| 原始 metadata 运动字段 | 有字段，缺连续同源样本验证 | 独立验证单位、坐标和采样时刻，不能直接继承 6668 的结论 |

最新转弯记录中，24 个互不重叠、满足转弯条件的 **0.5 秒窗口**，航向增量误差中位 **0.416°**、95% 分位 **1.441°**、最大 **1.775°**；全段持续积分仍有约 **9°** 航向差。统计基于固定换轴和 deg/s，没有调整时间倍率。它支持“短时辅助候选”，不支持“已标定、可以长时间接管”。

最小接入路线是：先旁路校验；满足条件后，只把已验证的航向增量用于配准初值或低权重约束，每次可信视觉/LiDAR 更新后重新开始短时传播。超时、源时间不连续或与可信观测明显冲突就放弃该增量，继续原定位路径；不重置地图原点，不放宽 `output_discontinuity`。0.5 秒是本次评估窗口，不是已验证可直接上线的通用超时参数。

**上述分量独立启用和短时接管属于后续接入方案，本轮没有实现或上线该功能。** 当前 `telemetry_motion` 是已有的完整 twist 候选接口，不应仅把 `fuse_velocity` 改成 true 来冒充“只融合 yaw”。真实 `sensor_msgs/Imu` 接口照常保留，不伪造加速度，也不承诺这路未核准的反馈能够解决 Z 高度漂移。

### 发送端需要核对的最小内容

最有效的证据是当前发送程序实际赋值代码：速度从哪个实体/刚体、哪个原点取得；是否经过世界到机体旋转；单位转换做了几次。只给 Actor 轴向图不足以证明速度字段属于该坐标系。

建议在同一物理采样步保存以下契约，metadata 或独立运动流均可使用：

```text
sample_seq             源采样序号，重发不增加
sample_time_ns         源物理采样时间，不能用接收/打包结束时刻代替
time_basis             simulation 或 monotonic；仿真暂停时语义明确
source_entity/origin   速度对应哪个刚体及参考点
linear_velocity_frame  body 或 world，以及轴向
angular_velocity_frame 同上，另明确角速度正转定义
linear_velocity_unit   m/s
angular_velocity_unit  rad/s 或 deg/s，接收端只换算一次
```

角速按机体系给出时，要结合对应的旋转规则；世界系速度转机体只应使用同一采样步的逆旋转一次。若速度以仿真时间定义，积分用相同时间轴上的差分；需要预测现实墙钟下的位置时，还需处理两个时钟的对应关系。不能把不明含义的 `elapsed_seconds` 当作仿真 dt。

拿到连续源时间后，使用固定坐标和单位复验直行、左右转、停止、重连及不同航向；对比积分增量和仿真参考增量。参考位姿只用于测试评分，不进入正式融合。验证通过的分量再逐项启用。
