# 定位跳变与视觉接管修复

工程：`/home/yanfa/P3/lidar_visual_fusion`

## 原因

平坦、重复的点云可以产生很小的点到平面残差，但地面切向位置仍不可靠。原版本允许这类结果更新完整位姿和配准地图；仅限制单帧速度，无法阻止多帧错误位移累积。

此外，旧代码存在两条放大问题的路径：视觉与 LiDAR 发生冲突时默认关闭视觉；正式输出已经拒绝的 LiDAR 位置，仍可能被用于重新对齐视觉，导致两者一起卡在 `output_discontinuity`。

相机视野和连续可见范围的裁剪用于高程建图/显示。定位配准使用完整 LiDAR 输入，不受约 6.7 m 的显示范围限制。

## 修改

1. **按几何方向判断可信度。** LiDAR 只修正可观测方向；退化方向采用同一视觉 epoch 的独立相对运动，或经标定的真实 IMU 预测。没有可靠运动参考时，该帧保持不可用，不把保留的旧位置伪装成新定位。
2. **在写入配准地图前检查。** 先用独立视觉增量初始化，检查收敛、运动连续性及弱几何下的视觉一致性，通过后才更新关键帧。
3. **保留正式输出保护。** `output_discontinuity` 没有放宽。只有通过正式输出检查的融合位姿可以作为视觉参考；新的参考还不能比视觉已有参考更不确定。
4. **仿真运动限制按车体中心计算。** 最大平移速度门限为 0.3 m/s，并考虑前置 LiDAR 在原地转弯时的安装偏移。根体素 1.0 m、降采样 0.1 m、最多 30 次迭代。
5. **保留真实 IMU 接口。** 未确认标定的仿真反馈不当成真实 IMU 使用。

## 车身点显示

`/T3/demo/vehicle_returns` 只发布当前帧的车身区域候选回波，最多 12000 点，供左侧 RViz 显示。它们不进入定位点云、累积点云、高程图或 P4。

当前区域是可配置包围盒，并非已标定的车身网格：`base_link` 中 X 为 ±0.591 m，Y 为 ±0.409 m，Z 为 −0.05～1.30 m。若传感器原始数据没有这些回波，显示也不会生成车身点。

## 已有验证

- 跳变记录：90 帧，原版末段最大相邻位姿变化约 0.907 m；修复后约 0.0073 m。
- 长记录：550 帧、12 分 51 秒，548 帧通过，2 帧因缺少可靠运动参考拒绝；末尾约 150 秒静止段的估计位置变化约 0.54 mm。
- 长记录的 LiDAR 配准耗时中位数约 0.137 s，95 分位约 0.342 s；不包含采集、图像前端、通信与地图发布。
- 同一长记录接入实际 EKF、Guard、高程 mapper：543 个正式位姿时间戳，未再触发 `output_discontinuity`，结束时定位有效；两次缺参考造成的短暂停发分别在 3 帧内恢复。高程更新到第 508 次，末尾静止段正式位姿变化约 1.16 cm。该集成测试以 2 倍回放速度运行，不是在线车辆试驾。
- 真实 ROS Guard 的合成故障测试：150 帧 LiDAR 失效期间视觉连续接管；黑屏/过曝停止使用视觉；双方失效停发；子地图恢复保持原坐标系；车身候选回波不进入 P4 高程。

这些结果用于检查已记录问题和回退路径，不是带真值的 ATE 或全场景精度保证。完整融合链路的最终记录见 `results/jump_vehicle_display_20260917/`。
