# 视觉恢复后仍显示定位不可用：待修问题

2026-09-16 只读检查 `results/run_20260916_180251`。机器由其他人使用，本次没有修改或重启算法，没有追加车辆控制。

## 现象与证据

用户观察到窗口持续显示“定位暂不可用”。检查时 LiDAR 配准未收敛；视觉状态一度为 `vision_enabled: true`、`vision_reason: healthy`，但 `visual_continuity.anchored: false`、`reason: new_visual_segment_requires_reference`。融合结果的朝向不确定性也超限。

该会话前 97 条视觉记录：89 次 `tracked`，6 次 `stereo_motion_disagreement`，1 次 `tracking_gap`，1 次首次初始化。六次双目运动一致性失败和一次时间间隔过大，把视觉从第 1 段重置到第 8 段。第 7、8 段随后又有多帧跟踪成功，但没有接回原地图坐标。

## 原因

`learned_tracker.py` 当前在一次几何估计失败后直接调用 `_seed()`，新轨迹以单位位姿为原点，替换旧关键帧。间隔超过阈值也直接重置。

`visual_continuity.py` 检测到新轨迹段后清除原对齐关系，等待同时间戳的可信参考。此时 LiDAR 仍不可靠，就无法重新建立地图位姿。当前帧能够跟踪，不代表已经恢复了旧地图的坐标连续性。

如果视觉一直保持同一段可靠轨迹且已有可信对齐，它可以在 LiDAR 不可用时持续独立输出。此次既有中间观测失败，也暴露了过于激进的重置策略和不完整的视觉恢复机制，不能概括为“视觉算法完全不能用”。

## 后续修复方向与验收

- 短暂失败先保留有限数量的可信旧关键帧；失败帧不作为可靠位姿输出，不立即覆盖参考。
- 恢复时先尝试与旧关键帧做双目几何重定位，检查匹配分布、重投影、尺度和运动一致性；成功才延续原轨迹。
- 真正失去视觉重叠时仍不能随意把新原点接到最后一个位姿，更不能靠放宽协方差阈值宣称恢复。
- 分别验证一帧失败、多帧失败、采集间隔抖动、光照失效和无重叠；之后再在独占设备时段验收实际运动。

**这是已定位原因、尚未完成修复的记录。** 不应把此前视觉接续合成测试的通过，解释为本场景已解决。
