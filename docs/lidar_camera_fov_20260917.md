# LiDAR 按视觉范围建图，边缘逐渐变稀

## 用途和启动

定位继续使用完整 LiDAR＋视觉融合；地图以 **双目共同视野为核心，保留近处连续的 LiDAR 测量**。遇到明显径向空档，空档后的孤立扫描线不再入图；此规则同时作用于左侧点云、右侧高程和发给 P4 的高程。在保留的连续区域内，真实高度观测完整参与融合，额外的渐变抽稀只作用于点云显示。双目深度点不混入这个模式。

当前 LiDAR 定位参数：根体素 1 米、输入降采样 0.1 米、最多 30 次迭代。0.1 米是用户指定的加密试用值；若运动时处理跟不上输入，备用值为 0.15 米，需要切换配置并重启生效，当前没有自动切换采样尺寸。

在 Orin 上，本套 P3 停止后，用下面的命令启动新会话：

```bash
cd /home/yanfa/P3/lidar_visual_fusion
./start_live.sh --profile config/simulation_lidar_camera_fov.yaml
```

原来的 `./start_live.sh` 仍是双目点云模式。启动器会检查已有会话，不能并行启动两套 P3 对同一接口发数据。完成离线验证后，按用户指令只重启了本套 P3，激活视野内 LiDAR 模式；没有操作 P4 或车辆。切换新会话会重新建立地图原点；与正在运行的 P4 联用时，需要使用者安排一致的会话和地图，不应直接混用旧地图。

## 怎样裁剪

1. 使用已有 `base_from_lidar` 把 LiDAR 点转到车体。
2. 按双目标定变换到校正后的相机坐标，分别投影到左右图像。
3. 双目共同视野内是显示的高密度核心；图像边缘外延约对应图像尺寸的 15%，显示用连续权重逐渐抽稀，角部采用圆滑过渡。
4. 距离按 **车体 XY 平面的水平距离**计算，15 米是候选测量上限，10～15 米有显示渐变；实际保留范围还要通过下述连续性检查，因此不保证保留到 10 或 15 米。
5. 显示使用固定世界栅格的确定性抽样，同一位置重复扫描不会不断随机补点，车辆静止时边缘也不会因随机抽样闪烁。车辆靠近后，新观测可以补密；已经建立的历史地图保留。点云数据库保留范围内全部测量体素，另外保存显示资格，重载时仍能恢复渐疏预览。
6. 用同时间戳的合格融合位姿将原始 LiDAR 测量点写入地图，不修改点的测量高度或伪造观测。

### 遇到空档后的统一裁剪

在显示抽样之前，把实际测量按车体水平方向分成 2° 小扇区。各扇区从 5 米以内的首个近处回波开始，按距离向外检查，出现超过 **0.25 米**的空档便停止；只有远处孤立回波的方向不作为连续区域。初始传感器盲区不算作中途空档。

空档前末端 0.6 米用于点云密度渐变；到截断边界后，点云、高程和 P4 接口都不再新增这些测量，未观测处保持 NaN。车辆靠近后，若新的扫描形成连续观测，可以继续补图。以前从近处连续扫描建立的历史地图保留。这是测量覆盖规则，**25 厘米是水平回波间距，不是障碍高度或配准阈值**。

```yaml
mapping_sources: [lidar]
lidar_mapping_crop:
  enabled: true
  image_margin_px: 0.0
  match_stereo_depth_limit: false
  image_feather_fraction: 0.15
  full_density_range_m: 10.0
  range_feather_m: 5.0
  sampling_cell_m: 0.1  # display only
  continuity:
    enabled: true
    sector_deg: 2.0
    max_gap_m: 0.25
    feather_m: 0.6
    seed_range_m: 5.0
elevation_fusion:
  bias_reference_source: lidar
```

明确设置 `full_density_range_m` 后，LiDAR 建图范围由这里的水平距离控制，不使用双目测深对应的 4.9 米限制。`sampling_cell_m` 只用于显示的稳定抽样；高程栅格仍是 0.2 米。将 `range_feather_m` 和 `image_feather_fraction` 设为 0 可恢复对应范围的硬边界，`enabled: false` 恢复完整 LiDAR 入图。

当前 LiDAR 预览体素为 0.15 米，发布上限 15 万点，窗口渲染上限 10 万点；RViz 恢复为 **Points、2 像素**，不使用方片或网格替代点。连续区域内仍可能看见正常采样纹理，算法不会制造扫描线之间的测量。未观测位置保持 NaN。`continuity.enabled: false` 可恢复只有视野和最大距离限制的模式。

这是几何视野裁剪，不计算相机与 LiDAR 安装位置差异造成的遮挡。范围依赖当前标定；软件测试不能替代实际标定。裁剪不依赖图像亮度或纹理，所以视觉短暂失效时，只要 LiDAR 定位和测量仍合格，这个模式仍能更新地图。

## 接口和检查

- `/T3/mapping/lidar_map`：经过显示抽稀的有界累积预览，`map` 坐标；停止后导出的 `lidar_map.pcd` 包含范围内全部测量体素。
- `/Car/T3/mapping/grid_map`：发给 P4 的车周围 **64×64 米**高程窗口，0.2 米/格，即 320×320 格，中心随当前定位移动。右侧界面独立跟车显示 **32×32 米**。
- `/Car/T3/mapping/global_grid_map`：累计高程；两种高程均为 0.2 米/格，发布周期 2 秒。
- 保留 `elevation`、`elevation_variance`、`observation_count`；P4 决定通行性。
- `map_statistics.json` 中 `mapping_sources=["lidar"]`、`lidar_mapping_crop.active=true`。`lidar_crop_last.kept_points` 是高程输入点数，`preview_points` 是显示抽样前景点数，`thinning_scope=display_only` 表示二者已分开。界面显示“LiDAR 建图（视野边缘渐疏）”。
- `lidar_crop_last.continuity` 单独报告空档裁剪的输入点数、排除点数、最大连续距离和 `scope=mapping_and_display`。这里的几何裁剪同时影响两侧显示及 P4；其后的显示密度抽样仍仅用于点云预览。

P4 持久地图会保留旧高度并忽略新的 NaN。切换统一裁剪配置不会自动删除 P4 以前缓存的远处区域；要完全按新范围查看，应由 P4 使用者安排新地图会话。本套启动脚本不重启 P4。

- 12 项几何回归通过，包括左右共同视野、相机后方、距离限制、非有限输入、非平行双目及安装姿态变换；新增 10～15 米连续权重、侧边圆滑过渡、稳定抽样和同列不同高度一致性。

- 原有双目单源、双源建图回归通过。
- 离线比较使用同一段同步图像／LiDAR、同一组已记录融合位姿，重建双目、完整 LiDAR 和视野内 LiDAR 三张地图。历史位姿协方差未记录，三路统一采用声明的固定协方差，因而这项比较衡量地图几何差异，不是完整在线复现或绝对定位精度。

### 初版 4.9 米硬裁剪的同段结果（历史）

以下数字对应最初 4.9 米硬裁剪，不作为扩展到 15 米后的精度结论。

358 组完整同步数据，时间跨度约 551 秒；该段融合位姿估计路程 4.59 米，Z 跨度 1.30 cm。三张地图都使用相同的位姿、20 cm 格子与高度融合代码；共同覆盖 1087 格，形成 1894 对水平／竖直相邻格。

| 项目 | 双目深度 | 完整 LiDAR | 视野内 LiDAR |
|---|---:|---:|---:|
| 相同格对中高差 >7 cm | 126 / 1894 | 0 / 1894 | 0 / 1894 |
| 相邻高差 P95 | 8.61 cm | 0.096 cm | 0.096 cm |
| 每帧点数中位数 | 316.5 | 63,392 | 5,561 |
| 最终观察到的格子数 | 1177 | 43,407 | 1542 |
| 高程计算与融合耗时中位数 | 12.2 ms | 452.7 ms | 24.9 ms |

视野裁剪另外约需 14 ms。耗时是此次离线进程中对应代码段的测量，不包括定位、消息传输、点云持久化和显示，不等同于整条在线链路延迟。完整 LiDAR 的格子数包含更大的观察范围，不能直接用它与双目计算精度排名。

在 898 个由另一时刻 LiDAR 扫描确认的近水平格子中，双目地图对该扫描局部平面的高度绝对差 P95 为 9.05 cm，视野内 LiDAR 为约 0.035 cm。后者体现本次仿真平面和 LiDAR 自身的高度一致性，**不是实车亚毫米精度，也不是独立定位真值**。同一组位姿下，换成 LiDAR 点显著减少了假高差，说明本段主要差异来自测深与地图观测质量，不能把这些高差全部归因于视觉定位。

完整数值：`comparison/analysis.json`；对比图：`comparison/comparison.png`。图中三列只显示共同观察到的格子。

初版试验会话：`results/live_mapping_20260917_132132_318592/`。当前会话以 `run_state.json` / `results/latest` 为准；启动时记录输入，便于后续复查用户手动运动时的高度变化。

### P4 外围黑色与未知颜色

P3 发出的 64 米窗口不等于 P4 当前显示图的尺寸。2026-09-17 本次只读检查中，P4 的 `/Car/T4/mapping/local_fine_map` 仅为 59×70 格，即约 11.8×14 米。`planning_snapshot_visualization.cpp` 的 `ProjectFineVisualization()` 调用 `WindowBounds()`，默认把显示窗口裁到已有地图范围；范围外露出 RViz 深色背景，不是 P3 把整圈 NaN 改成障碍。

当前 P4 普通未知格编码为 -1，当前 Map 显示中呈灰绿色；可通行编码 0，障碍编码 100。该次消息有 3783 个未知格、207 个可通行格、140 个障碍格。障碍格位于约 X=7.7～10.3 米、Y=3.7～5.9 米，其中部分是膨胀到无高度观测的位置，因此 NaN 也不保证最终通行状态一定为未知。

若需要 P4 将完整显示窗口绘成未知色，应在 P4 的显示输出保留窗口尺寸、未覆盖处填 -1，并保留已有障碍膨胀结果；P3 不应把 NaN 改为零高度或可通行。本轮未修改 P4。证据：`p4_color_audit.json`、`p4_black_height_overlap.json`。
