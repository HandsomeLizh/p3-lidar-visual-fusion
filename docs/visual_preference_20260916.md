# 仿真中优先使用合格视觉位姿

`config/simulation_live.yaml` 新增：

```yaml
pose_source_preference: visual
```

省略此项或设为 `balanced` 时，按原有不确定性比较与滞回规则选择输出。其他配置没有开启视觉偏好。

## 运行逻辑

1. 先检查曝光、纹理、双目几何、运动一致性、时间戳、轨迹对齐和协方差。优先级不能覆盖这些检查。
2. 两路合格时，仿真配置优先从连续视觉轨迹发布正式位姿和主 TF。稳定跟踪期间保留原地图对齐，不逐帧复制 LiDAR 的位置变化。
3. 视觉失效或观测过时，使用合格的 LiDAR／EKF 结果。视觉恢复需通过连续帧确认，并在需要时使用同时间戳参考重新对齐。
4. 两路都不合格时停止可信定位。切换仍受原有位置、转角和同时间戳累计修正限制，差异过大时不会强行接上。

LiDAR 继续提供点云、高程建图、运动交叉检查、定位后备和子图恢复。地图和 RViz 使用同一个正式位姿。当前仍没有纯视觉深度建图后备。

查看 `/fusion/status` 中的 `pose_source_preference`、`output_source`、`localization_valid` 与 `visual_continuity`。视觉偏好不代表当前一定有合格视觉输出。

## 验证

`tests/test_visual_preference_ros.py` 在隔离域 80 中使用实际融合节点和合成前端消息，检查：

- LiDAR 带轻微抖动时，正式位姿实际跟随视觉增量，而非只改变状态标签。
- 黑屏切回、视觉过时切回、恢复后重新使用视觉。
- 视觉突跳仍拒绝；两路失效停发；位姿和 TF 一致。
- 测试轨迹的切换附加位移最大为 0.04 米。

这不是 UE 实车运动测试，也不是 ATE。共享会话未重启，新配置在下一次启动建图时生效。另见 [视觉失效恢复](visual_recovery_gap_20260916.md) 和 [LiDAR 配准修复](voxel_neighbors_20260916.md)。
