# 视觉与 LiDAR 的互补输出

216 的后续交互实验发现：两路健康时直接选择整条视觉轨迹，会丢掉融合器仍可用的高度、倾角约束。小的视觉误差不断积累，可能把平地叠厚并形成假障碍。104 已按这一发现适配候选版本，实际部署状态见 [实车验证](HARDWARE104_RECOVERY_20260916.md)。

## 输出策略

104 使用 `pose_source_preference: fused`：

1. 两路健康且滤波位姿合格时，使用融合位姿；保留 LiDAR 的几何约束和 IMU 预测，视觉通过车体运动约束进入融合。
2. LiDAR 不可用，或者滤波位姿过期、协方差超限、违反连续性时，允许已有可信地图对齐的合格视觉接管。
3. 视觉黑屏、过曝、几何异常或过期时拒绝视觉；合格 LiDAR／融合结果继续输出。
4. 两路都不可信时不发布新的可信定位，TF 与正式位姿保持一致。

`visual` 模式也采用此融合优先、视觉后备逻辑，并保留可选视觉权重设置。`balanced` 保留历史按整体不确定性比较的策略，供原配置兼容。

`visual_motion_information_scale` 允许 1～2；它调整进入融合器的视觉速度协方差。216 实验用 1.25；104 保持 **1.0**，没有照搬仿真加权。它不能绕过质量门限。

短暂视觉失败最多保留两个可信关键帧，30 秒内可以尝试几何恢复；这不是放宽消息新鲜度。参考过期或确实没有重叠时，仍需新的同时间戳地图参考。

## 验证范围

隔离 ROS 测试使用真实 guard 和地图代码，合成前端／滤波消息：

- 注入逐帧高度和倾角漂移时，融合输出保留地面约束；平地假障碍消除，测试石块仍保留。
- 黑屏、过曝和过期视觉回退，LiDAR 失效及滤波发散时视觉接管，恢复后回到融合。
- 拒绝视觉突跳，双路失效停发，正式位姿与 TF 一致。

这些是故障处理回归，不是实际运动 ATE。测试脚本为 `tests/test_visual_preference_ros.py`。
