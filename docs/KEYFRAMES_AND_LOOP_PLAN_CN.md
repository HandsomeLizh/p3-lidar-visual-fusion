# P3 关键帧保存与回环：后续接入方案

更新：2026-09-17。本文是设计建议，**尚未实现的功能不能按现有功能使用**。当前启动方法见桌面的《P3融合建图_使用说明.md》。

## 1. 三件事分别解决什么

| 功能 | 作用 | 当前状态 |
|---|---|---|
| 短时关键帧恢复 | 暂时看不清后，重新匹配之前的可信画面，接续原坐标段 | 已实现：内存参考、120 秒窗口、几何检查和两次确认 |
| 关键帧落盘与重定位 | 把特征和对应三维点存到磁盘，重启后识别自己在旧地图的哪里 | 待实现；当前保存高程图不包含完整的重定位数据库 |
| 完整回环 | 再次经过旧地点时，纠正累计的轨迹误差，并同步修正地图 | 待实现；需候选检索、几何验证、位姿图优化和地图重建 |

回环需要重新看到可识别的旧区域。没有重访，或光照和地形都无法提供可靠约束时，不能指望回环消除漂移。当前 LiDAR 退化检查、独立视觉增量和跳变保护仍要保留。

## 2. 建议先做关键帧保存

保留当前 VoxelMap＋XFeat/LighterGlue 前端，只给可信关键帧增加后台保存。关键帧应按运动、转角、视野变化和质量选择，不能把每一帧都长期放进内存。

建议每个关键帧保存：

- 唯一编号、会话编号、视觉坐标段编号、采集时间、坐标系、位姿及不确定性。
- 左图特征点与描述子、对应的双目三维点，以及必要的索引关联。
- 相机内外参、图像尺寸、模型和描述子版本，加载时核对兼容性。
- 用于重建高程和点云的局部坐标测量，或关联的局部子图；保存测量时间、来源、入图掩码及不确定性。
- 可选的压缩缩略图，用于人工检查；日常不必保存每帧完整图像。

保存采用有界后台队列和磁盘索引，内存只保留近期与正在查询的关键帧。磁盘写满或队列积压时明确报告保存异常，不能卡住实时定位。

加载关键帧库后，应先通过当前画面与旧关键帧的几何匹配确定位置。**不能直接把上次关机位置当作本次开机位置。** 新会话不应静默覆盖旧库；写入与索引需要一致的检查点和版本。

## 3. 再加入轻量回环

建议流程：

```text
可信关键帧 / 局部子图
          ↓
找少量可能重访的旧地点
          ↓
视觉三维几何验证 / LiDAR 子图验证
          ↓
跨帧确认，拒绝重复石块造成的假匹配
          ↓
位姿图优化
          ↓
重建受影响的地图块，同步位姿、TF、地图版本和 P4 路径
```

### 候选检索

第一版可先用 **ORB＋DBoW3** 检索少量视觉候选，再复用现有 **XFeat/LighterGlue＋双目三维点＋PnP** 验证。DBoW3 负责快速找相似画面，不直接决定回环成立。该库支持二进制和浮点描述子；若直接检索 XFeat 描述子，需要与它匹配的词典，不能套用 ORB 词典。[DBoW3 官方代码](https://github.com/rmsalinas/DBow3)

后续可增加独立 LiDAR 候选通道，例如 **MapClosures**。它通过局部点云的密度图寻找回环，并提供 C++、Python 接口。它是候选与几何检测模块，仍需接入本项目的三维验证、退化判断和优化后端。[MapClosures 官方代码](https://github.com/PRBonn/MapClosures)

定位与回环使用完整有效 LiDAR 局部子图；当前相机视野裁剪属于建图范围策略，不宜把回环也限制在很小的一块平地上。平坦、重复石块场景是否能可靠识别，必须用本项目数据验证。

### 几何检查

- 相似图片只是候选，还需要足够的三维几何支持、内点空间分布和重投影一致性。
- LiDAR 小残差不代表所有方向可信，要继续检查方向可观测性和重叠情况。
- 多个连续关键帧应支持相同的相对位置关系，再加入回环约束。
- 视觉与 LiDAR 都可靠时应交叉验证；某一路失效时，可允许另一路在充分验证后独立提供约束。
- 优化采用抗离群约束，并保留拒绝、隔离和回退错误回环的能力，不能用回环绕过 `output_discontinuity`。

### 位姿图优化

把关键帧作为节点，可信相邻运动和确认的回环作为约束，后台修正各关键帧之间的位置关系。当前没有可信重力参考，建议先按 **六自由度 SE(3)** 设计，即三维位置加三维转角；不能直接把带可靠 IMU 的四自由度假设套过来。

结构可参考 **VINS-Fusion 的 loop_fusion**：源码包含回环检索、连接验证、位姿图保存与加载，并分别提供有 IMU 的四自由度优化和无 IMU 的六自由度优化路径。借鉴模块边界，不能直接把它当作本 ROS2 项目的即插即用组件。[VINS-Fusion 位姿图源码](https://github.com/HKUST-Aerial-Robotics/VINS-Fusion/blob/master/loop_fusion/src/pose_graph.cpp)

## 4. 对本项目最关键的是地图一起改

**只把轨迹拉回来，高程图不会自动变正确。** 现在高程融合会将多次观测合并到同一格子，仅有融合后的高度统计，通常无法完整拆回各帧原始贡献。

因此，关键帧保存阶段就应保留足够的局部点云或子图数据。回环后用优化过的关键帧位姿重新投影，重建受影响的高程块和点云；否则原来的重影、台阶和错位高度仍留在地图里。

建议让连续的局部 `odom` 服务实时运动，全球修正通过 `map → odom` 表达。但当前接口使用固定单位变换，接入前需要同步调整建图、显示、Guard 和 P4 的坐标使用，不能只改一条 TF。

完成校验后，应成套发布新的地图版本、位姿和坐标变换，并通知 P4 废弃旧规划路径、重新规划。只做平滑显示不能解决旧路线与新地图不一致的问题。

## 5. 可以参考哪些项目

| 参考项目 | 主要借鉴内容 |
|---|---|
| [VINS-Fusion / loop_fusion](https://github.com/HKUST-Aerial-Robotics/VINS-Fusion/tree/master/loop_fusion) | 视觉候选检索、几何连接、位姿图保存与加载；适合作为首版结构参考 |
| [ORB-SLAM3 / Atlas](https://github.com/UZ-SLAMLab/ORB_SLAM3/blob/master/src/System.cc) | 已有 Atlas 保存、加载与地图管理入口，可参考跨会话数据管理；不必替换当前整套前端 |
| [MapClosures](https://github.com/PRBonn/MapClosures) | LiDAR 局部点云回环候选与验证组件 |
| [KISS-SLAM](https://github.com/PRBonn/kiss-slam) | 将 KISS-ICP、MapClosures 和 g2o 组成 LiDAR SLAM 的模块组织方式；本项目仍可保留 VoxelMap |

上面是官方实现的参考方向，不代表已经测得它们在这台 Orin 上的速度或精度。接入时应固定依赖版本，核对许可证，并记录资源开销。

## 6. 按这个顺序推进

1. **保存和加载关键帧**：验证重启读取、版本不匹配拒绝、后台保存不阻塞定位。
2. **旧关键帧重定位**：先只报告候选和验证结果；黑暗恢复、重复石块和视角变化都要测试。
3. **回环与地图重建**：对有真实重访的录制轨迹，检查轨迹误差、高程接缝和错误回环拒绝能力。
4. **P4 联动与在线验收**：检查地图版本切换、局部路径对齐，以及实际内存、GPU 占用和定位延迟。

优先做“落盘关键帧＋严格重定位”，再接位姿图和地图重建。这样每一步都能独立验收，也能控制工程规模。完整回环完成前，当前日常启动命令保持使用说明中的两条入口。
