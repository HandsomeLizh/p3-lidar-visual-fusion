# 车后方高程变黑：原因与修复

更新：2026-09-16。

## 现场证据

车后方检查的 1500 个栅格全部仍有高程，但全部被标成了黑色障碍。当前显示中，黑色表示障碍，深灰表示未观测。

原统计把同一格建图以来的最高、最低高度之差作为障碍厚度。位姿高度缓慢变化后，即使每次看到的都是平地，跨帧高度范围也会持续增大。现场后方范围约 0.21～0.36 m；连续采集的 10 帧中，单帧同格高度范围的 95 分位只有约 0.0012～0.0014 m。

记录位于 `results/rear_map_audit_20260916/`。这不是窗口裁剪或历史高程删除；本次运行检查时没有缓存淘汰。

## 改动

- `height_range` 改为各次独立扫描内部高度范围的最大值；同一帧共同的高度偏移不会累积成障碍厚度。
- 跨帧高度变化仍保留在高程均值、方差和内部原始极值中。
- 已观测的真实高低差继续保留；后续只看到一个表面、没有重新扫描，都不会自动清除旧障碍。
- 经连续自由空间观测确认移除旧点后，重建栅格不会把不同时刻的剩余点重新当成一帧计算障碍厚度。
- 局部规划地图、全局显示地图采用同一统计。缓存增加一个 float32 层，默认 64 个 128×128 瓦片最多增加 4 MiB，仍受原缓存上限约束。

## 验证范围

- 13 项回归通过，覆盖地面高度缓漂、真实石头、遮挡、旧障碍清除、负坐标、缓存淘汰、回读和导出。
- 隔离 ROS 域 81：模拟 0.36 m 高度漂移和 30 m 移动，局部与全局地面不变黑，真实石头保留，离开局部窗口的历史高程保留，未观测区域仍未知。
- 原有动态障碍 ROS 测试通过：新障碍加入、连续观测清除、位姿不确定时重置清除确认。
- 刚才采集的 10 帧真实数据离线重建：后方已观测 963 格，黑色障碍 0 格；未观测或邻域不足的格保持未知。
- 原有视觉偏好与失效接续 ROS 回归通过。
- 六个 ROS 包编译通过。

上述移动是测试输入，不是现场自动驾驶或 ATE 精度验证。本次修正障碍统计，并未消除定位本身的全部漂移。

## 生效方式

运行中的 Python 节点不会自动加载新代码，需要按使用说明停车、停 P4，再重启 P3/P4。

旧地图缺少逐帧高度范围，不能准确反推出哪些历史极值来自漂移，因此保留旧结果，新建一次地图进行验证。读取旧文件仍保留原有保守障碍信息，不会擅自把旧障碍改成可通行。

新运行的 `map_statistics.json` 中应出现：

```json
"height_range_basis": "maximum_within_scan_relief"
```
