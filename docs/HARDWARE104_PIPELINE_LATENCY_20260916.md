# 104 地图更新延迟优化

日期：2026-09-16。基线 `4ca9598`。正式目录 `/home/yanfa/P3/lidar_visual_fusion`，启动方式保持原样。

## 修改与原因

性能剖析显示，同一帧约 0.54 秒的地图处理中，点云存储占约 0.36 秒，其中大量时间花在重复体素的数据库检查、插入和 Python 数据转换。

- 缓存前一帧中已经成功提交的体素索引，跳过确定重复的写入。逐轴比较整数索引，不依赖可能碰撞的哈希；保留原来每个体素的第一个点。
- 缓存最多 65,536 个索引，持有内存不超过 1.5 MiB，不随累计地图增长。新体素仍完整写盘。
- 障碍清除前使缓存失效，允许同位置后来重新出现的障碍再次入图。数据库事务失败时，不把未提交的点写进缓存。
- 全局概览按栅格批量计算最小值、最大值和观测计数，替代逐点散写。高程融合准则、地图分辨率、点云密度、未知区域表示均沿用基线。
- `/fusion/map_status` 增加 `map_stage_sec`、`queue_wait_sec_by_source`、`voxel_cache_mib`、`cached_voxels_last_scan`，方便区分处理、排队和缓存开销。

本轮仅修改 Python 建图和测试代码。保留雷达 4 线程、0.2 m 降采样、20 次迭代上限，以及 0.4 秒位姿修正等待和双目置信度门限。

## 同输入验证

六帧已录真实点云，固定相同位姿，按顺序处理：

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 地图计算中位数，不含最后一帧剖析 | 0.518 s | 0.295 s |
| 持久化体素数 | 61,652 | 61,652 |
| 高程、计数、M2、最小值、最大值数组 | 基准 | 完全相同 |
| 存储体素索引及 XYZ 哈希 | 基准 | 完全相同 |

30 项相关回归通过，覆盖缓存上限、重复扫描保留首点、写入失败回滚、障碍删除后重新出现、概览计数饱和、地图边界和异常输入。ROS 双目补图、混合队列及 20 Hz 输入压力测试通过；合格双目点进入局部与全局栅格，未知区域保留。

另外用每帧 5 万点测试缓存边界：重复扫描的点云存储中位数 0.239→0.074 秒；连续四帧完全不重叠的新区域为 0.314→0.339 秒，增加约 25 ms。两种情形存储内容均一致。缓存对重叠观测收益较大，对全新区域存在比较开销，不能声称所有场景都会等比例提速。
