## 已实施的重点修复

| 环节 | 发现 | 处理 |
|---|---|---|
| LiDAR 不确定性 | 方向性退化被当成整帧不可用，旧长段所有 LiDAR 观测被拒 | 使用噪声加权几何信息得到完整协方差；弱方向降权，配准残差/重叠明显异常仍拒绝 |
| 仿真坐标 | 发布端已转换 ROS FLU，继承的 LiDAR 外参仍含另一套传感器轴 | 按发布端源码修正轴变换；首帧地面和转向检查通过，没有按参考轨迹拟合外参 |
| 视觉融合 | 累计视觉高度漂移使整个位姿被拒，弱 LiDAR 时无法接替 | 使用同一视觉 epoch 内的车体运动；速度协方差按相对运动和时间间隔平方传播，视觉绝对位姿不参与当前 EKF |
| 视觉恢复 | 原点重置及置信度波动导致长时间不能恢复 | 不跨 epoch 计算运动；中等置信度按协方差降权；跟踪恢复后使用新 epoch 内的局部运动，无须强行拼接原点 |
| 位姿与地图一致性 | EKF 同时间戳修正被中间节点丢弃 | 转发修正位姿，更新轨迹末点和缓存；建图留出有界等待时间 |
| 到达顺序与转弯 | 视觉先到时跳过同帧 LiDAR 检查，EKF 又拒绝正常 LiDAR | 有界等待同帧 LiDAR；保留视觉创新门限，移除已通过前端检查的 LiDAR 的重复硬拒绝 |
| 图像传输 | 原始大图通过 DDS 传输造成掉帧 | bag 对照提前执行相同灰度缩放，直接发送 640×536 小图；已验证模型输入像素等价 |
| 模型启动 | CUDA 首次初始化可能挤占第一帧处理预算 | 接收输入前进行一次预热，启动器等待视觉就绪 |
| 构建与部署 | 改了 Python 源码，ROS 仍加载安装目录旧副本 | 启动检查源码、实际导入的 Python 文件及运行二进制；记录每轮运行清单，拒绝不一致 |
| 回放收尾 | 停钟后定时器不再处理末尾点云，统计也可能滞后 | 保存服务主动处理待入图队列并刷新统计；测试必须满足每帧入图、无残留队列；写统计失败时报告错误 |
| 实时队列 | 满队列不断淘汰最早帧，可能使等待视觉修正的帧永远不能入图 | 满时主动舍弃新输入，保留已等待的帧；20 Hz 小型点云压力回归验证持续入图、队列不超过 4 |
| 失联判断 | 稀疏 bag 的宽松超时被带到高频实时输入 | 依据最近到达周期缩短失联门限，保留配置上限和最低等待时间；快速输入失联与稀疏输入回归均通过 |
| 验证脚本 | 检查器失败仍可能生成“完成”标记 | 修复 NumPy 布尔序列化；监督脚本要求接口报告存在且检查通过 |

## 各部分检查结论

### 1. 算法与融合

- VoxelMap 内部点面匹配、地图更新和无 IMU 运动模型保持原实现；修复主要作用于发布的不确定性与融合接入。
- XFeat/LighterGlue 保持稀疏特征预算、双目几何检查、PnP 内点比例和覆盖率检查。重复纹理不能仅靠“检测到很多特征”判定有效。
- 光度、几何、时效和运动合理性分别检查。斜向强光仍有足够可用纹理时允许继续，不因为画面亮就一律禁用。
- 灰度图是正常输入，不能当作异常。完全无可用纹理时视觉退出，LiDAR 继续。
- 两路都不能提供合格观测时，不把预测或旧位姿包装成新的可靠传感器证据。`/fusion/status` 的有效性与原因应纳入规划端判断。
- 当前协方差下限是工程设置，尚非经过实车标定的完整误差模型。尤其是长期里程计漂移、共享初始化和真正全平面退化，不应仅凭本次轨迹保证精度。
- 修正后的 short 中，允许 0.5 秒参考插值的近似诊断为视觉 ATE 9.88 cm、LiDAR 16.93 cm、融合 10.82 cm；LiDAR 最大误差 1.04 m，融合仍有 0.44 m 尖峰。次日平坦路线恢复了 174/174 帧建图，但融合 ATE 0.503 m、最大误差 2.36 m。当前不能宣称总能选中最准确的来源，也不能把高覆盖率等同于高精度。

### 2. 异常与边界

检查了：黑屏、过曝、低照度、局部强光、灰度输入、重复/逆序时间戳、迟到视觉、前端重启、两路失效、恢复过渡、非法位姿/协方差、IMU 缺失/断流/错误坐标/NaN、查询超限、缓存淘汰与磁盘写入失败。

有 IMU 时仍须满足标定、初始化和时间覆盖条件。当前 bag 没有 IMU；相关合成测试仅证明接入和回退逻辑，不能证明实车惯性精度。原始旋转 LiDAR 扫描仍需要上游去畸变。

### 3. 内存、队列与保存

| 项目 | 当前上限/方式 |
|---|---|
| 视觉 | 每幅最多 1024 特征；1 对待处理图像；左右同步各 2 帧 |
| LiDAR 定位地图 | 当前区域约 80 m 半径，最多 10000 根体素 |
| 高程缓存 | 最多 64 个 128×128 块，另设 128 MiB 缓存预算 |
| 常规地图窗口 | 64×64 m，分辨率 0.2 m，320×320 格 |
| 点云显示 | 最多 150000 点；完整细体素保存在 SQLite |
| 历史位姿/显示轨迹 | 1200 个缓存位姿；显示轨迹最多 5000 点 |
| 资源保护 | 进程树 RSS 超软上限可关闭本目录可视化进程；严重压力持续时停止本目录运行 |

地图增长主要转移到磁盘，不能理解为整机内存完全恒定。DDS 缓冲、Python 对象、SQLite、GPU 和 RViz 都需要计入实际峰值。进程 RSS 求和可能重复计算共享页，因此报告的是进程树 RSS，而不是独占物理内存。

### 4. 地图发布与规划接口

- 正式位姿保留 `/T3/semantic/current_pose`，类型为 `nav_msgs/msg/Odometry`；增量地图保留 `/T3/semantic/incremental_map`。
- 局部高程图、通行栅格、点云、区域查询和地图版本沿用既有接口。地图按周期、有更新才发布；完整 PCD 在停止后流式导出。
- 完整高分辨率全局图超出容量时明确报告不可用，保留局部图、区域查询与低分辨率全局概览。不能把裁剪窗口当成完整全局地图。
- 全局 NPZ 可能停留在尚未超限时的旧版本。规划或离线读取必须检查 revision，超限后的完整最新数据以 SQLite/分块快照为准；最终静态展示重新从最新块生成，不能盲用旧 NPZ。
- `map → odom` 当前为恒等静态变换；唯一主动态 TF 由 EKF 发布。本次新增 TF 与正式位姿同时间戳一致性检查。
- 规划端实际订阅、未知区域策略与运动控制闭环仍需要规划程序共同联调；话题检查通过不等于完成闭环验证。

### 5. P3 最新高程不确定性

已检查原 P3 的 `elevation_fusion.py`、`semantic_grid.py`、`tiled_semantic_map.py` 和输出/快照代码。其最新方差融合可以复用，详细接入位置见 `p3_gridmap_uncertainty_review.md`。

需要区分：`elevation_variance`/`roughness` 是格内高度散布；`elevation_estimate_variance` 才是高度估计方差。本目录目前仍使用已冻结的原高程统计，**没有宣称已接入最新高度估计方差**。

后续优先复用原 P3 这项小改进，同时补齐缓存序列化、快照版本和查询层。仅两个 float32 状态，在 64 块缓存中约增加 8 MiB 数组；无需另建地图框架。位姿协方差传播和测距噪声标定应同步验证，不能直接相加转角和平移方差。

### 6. 可视化

沿用 P3 的同一套 RViz/高程面板、统一高度着色及轨迹显示。相机预览接到算法实际使用的小图话题，能看到所施加的干扰。显示点云单独限量，保留磁盘完整点云；显示频率不决定定位频率。长图通过概览、局部窗口和区域查询查看，不持续传输整张高分辨率图。

## 暂不扩大的部分

以下作为有依据的后续项，不在此次堆入新架构：

1. 实时上游图像也采用等价小图传输：当前优化已接 bag，实时采集端需配合；保持标定、图像尺寸和时间语义一致。
2. 完整高频传感器链路仍需实测。已补上按到达周期判断失联及不饿死地图更新的有界队列；20 Hz 回归仅覆盖小型点云、给定里程计与 mapper，不代表整条视觉／LiDAR 链路达到 20 Hz。
3. 原 P3 的 `pose_stamps` / `trajectory_file_stamps` 等完整历史用于回环/地图重建，显示轨迹上限不等于这些历史有上限；极长运行应按功能需求另测磁盘化，而非直接删除历史。
4. 原 P3 区域查询中的非法参数异常应在服务边界统一转换成失败响应；本目录已有空地图失败约定。此项记录给原项目维护，不越过本次隔离目录改动。
5. 长期视觉漂移协方差、完全退化平面、真实眩光和实车动态扫描需要额外数据验证。先完善这些证据，再考虑更重的回环或图优化。
6. bag 循环或仿真时间回退应新建运行并重启整条链路。当前会拒绝逆序观测，不跨时间回退把新旧地图拼接在一起。
7. 后续优先改善长时间完全平面退化、错误但自信的匹配及协方差校准。本轮先完成同一套参数的跨路线对照；不要为抹平某条路线的尖峰随意改权重或引入大框架。
