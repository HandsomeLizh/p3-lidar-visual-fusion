# P3：LiDAR＋视觉定位与建图

面向 ROS 2 Humble 的 **VoxelMap＋XFeat/LighterGlue** 融合建图模块。输出位姿、轨迹、高程栅格、LiDAR 点云和增量地图，沿用 P3 的规划接口与 RViz 显示。

**文档入口：[简明使用说明](docs/QUICKSTART_CN.md) · [目录与常用命令](docs/DIRECTORY_CN.md) · [完整文档索引](docs/INDEX_CN.md)。** 最近一次运行通过 `results/latest/` 访问，真实目录和进程以 `run_state.json` 为准。

## 算法

- LiDAR：VoxelMap 平面及方向协方差、配准质量检查、收敛检查；无 IMU 时失配回到最后可信状态，停止无观测支持的速度外推。逐帧定位，移动 0.1 米或转动 1 度后才向内部配准地图加入新视角。
- 视觉：轻量学习特征与稀疏匹配，检查曝光、对比度、清晰度、特征覆盖、双目几何和运动一致性。短暂失败保留最多两个可信参考帧，几何恢复成功后延续原轨迹。
- 融合：视觉提供车体运动约束，支持迟到观测修正；实时模式在 LiDAR 不可用时，允许连续、合格的视觉独立发布位姿、主 TF，并用仍有效的点云继续建图。视觉不合格时使用合格 LiDAR；两路均不合格才停止定位输出。输出仍检查协方差、位移和转角，包括同时间戳的累计修正。
- 恢复：合格视觉为 LiDAR 提供同时间戳初值；持续失配时尝试候选局部子图，经多帧确认后接回。候选失败不打断合格视觉，也不清空累计地图。见 [视觉接续与子图恢复](docs/visual_recovery_20260916.md)。
- IMU：可选；当前演示未启用经过标定的 IMU 融合。接入条件见 [可选 IMU](docs/optional_imu.md)。
- 地图：磁盘分块高程、有限内存缓存、有界点云预览和输入队列。全局消息包含障碍层；旧障碍须经多帧真实 LiDAR 射线确认已空出后清理，未重新观测的区域保留。
- 静止检测：实时模式结合双目特征位移、视觉运动和点云变化，连续确认后使用零速度约束。可选车辆速度反馈用于否决误判；零反馈不能单独证明静止，断流时回退到图像与点云判据。
- 车辆反馈：保留“X 后、Y 下、Z 左”的可选机体系转换；现有记录尚未通过方向、尺度和时钟一致性核验，默认关闭，不参与积分。保留实车标准 IMU 接口。详见 [车辆速度反馈与 P4 核查](docs/velocity_feedback.md)。

实时仿真配置在两路合格时[优先使用视觉位姿](docs/visual_preference_20260916.md)，视觉失效或过时后切回合格 LiDAR／EKF；普通配置保留按不确定性选择。当前几何建图仍需要有效点云，尚未实现纯双目深度后备建图。

## 在现有 P3 机器上启动

先启动 UE，再开两个终端；车辆由人操作控制窗口。

**终端 A：采集＋车辆控制＋控制窗口**

```bash
cd /home/yanfa/P3/lidar_visual_fusion
./start_simulation_sources.sh
```

**终端 B：建图＋RViz**

```bash
cd /home/yanfa/P3/lidar_visual_fusion
./start_live.sh
```

采集与控制使用 ROS 域 **10**，建图使用域 **57**，传感器转接自动启动。采集脚本会复用匹配的已有进程，缺少控制窗口时补开窗口。启动脚本不选择驾驶模式、不设置非零速度。

需要选点导航时，在第三个终端启动 P4：

```bash
bash /home/yanfa/P4/scripts/navigation.sh start
```

等待 P4 就绪，在本组合窗口右侧点 **设置目标**，于已观测的可通行栅格按下并拖动设定朝向，松开发送给 P4 规划和行驶；Esc 取消。启动本身不发送目标。P3 重启后需在车辆停稳时重新启动 P4，使其重新对齐坐标。见 [简明使用说明](docs/QUICKSTART_CN.md#3-接入-p4在栅格上选点导航)。

结束时先由人停车，再在终端 B 按 Ctrl+C，保存地图并结束建图。终端 A 管理自己启动的采集、控制和 GUI。GUI 保留原 P3 的关闭停车行为。

历史 bag：

```bash
./start_short_bag.sh fusion          # 现有 P3 的 short bag
./start_long_bag.sh                 # 现有 P3 的长 bag
./status.sh
./save_map.sh
./stop.sh
```

完整操作见 [简明使用说明](docs/QUICKSTART_CN.md)。**新机器先看 [环境与依赖](docs/SETUP_CN.md)**：仓库提供本模块源码，原 P3 的采集、控制 GUI、定制 RViz 和 bag 属于外部依赖。

## 当前 RViz 设置

组合窗口实际加载 [config/p3_visual_window.rviz](config/p3_visual_window.rviz)，由 `scripts/p3_visuals.sh` 指定；这份配置随源码版本同步。固定坐标系为 `map`。左侧显示全局点云，显示采样为 **0.25 米、最多 10 万点**；右侧默认跟随车辆显示 **32×32 米**，可切换全图。已识别障碍显示黑色，未知区域为深灰色；绿色显示 P4 全局路线，紫色显示局部路径，橙色为已行驶轨迹。

右侧显示和选点代码独立保存在 [visual/](visual/)，不修改原 P3 或 P4。重复地图直接复用已生成图像，只绘制当前视窗；路径和显示缓存均设上限。

[config/fusion.rviz](config/fusion.rviz) 是独立 RViz 的备用配置。当前组合窗口仍依赖原 P3 的 Qt 程序和显示插件，配置文件已独立保存在本仓库。

## 地图更新与规划接口

地图由有效 LiDAR 帧配合同时间戳的融合位姿更新；当前实时配置等待 1.6 秒，让视觉修正参与入图位姿。局部地图每 2 秒检查发布，有新内容才发送；规划端使用跟随车辆的 64×64 米窗口。全局地图仍每 2 秒触发发布，右侧从中截取跟车的 32×32 米视窗。压缩保存交给有界后台线程。上述周期是调度目标，实际延迟还受建图耗时影响。

采集请求上限已设为 2 Hz、额外批次等待为零。2026-09-16 同一驻车场景前后各 30 批实测，接收端重叠解码后由平均 1.83 秒降到 1.36 秒一批（约 0.74 Hz），尚未达到 2 Hz。每批约 72 MB，当前 UE 数据链路为 1 Gbps。现有启动脚本自动优先使用已构建的独立采集副本，构建方法见环境说明。

| 话题（ROS 域 57） | 类型 |
|---|---|
| `/T3/semantic/current_pose` | `nav_msgs/msg/Odometry` |
| `/T3/semantic/trajectory` | `nav_msgs/msg/Path` |
| `/T3/semantic/incremental_map` | `t3_interfaces/msg/IncrementalSemanticMap` |
| `/T3/mapping/elevation_map` | `grid_map_msgs/msg/GridMap` |
| `/T3/mapping/lidar_map` | `sensor_msgs/msg/PointCloud2` |

坐标、地图查询和资源限制见 [接口与资源约定](docs/接口与资源约定.md)。地图、日志和轨迹保存在每次运行的 `results/` 子目录。

## 已完成的验证

本轮 [地图、选点与显示验证](docs/map_visual_20260916.md)：障碍黑色显示、连续观测清除、未知区域保留和定位异常时停止清除均通过测试；隔离 ROS 域接通真实 P4 规划器与控制器，通过软件车辆向人工目标行驶并持续建图。界面完成 600 次刷新检查。**测试未控制真实 UE 车辆，也不是在线定位精度验收。**

针对 [现场连续失配](docs/live_failure_20260916.md)，已增加 [视觉接续与子图恢复](docs/visual_recovery_20260916.md)，实时配置默认开启。隔离完整链路中，LiDAR 连续失败 24 帧、候选子图撤销 4 次期间，视觉位姿和地图均持续更新；后续子图恢复通过。初次失配的场景原因仍未完全确定，**新代码的实际行驶精度尚待验证**，不能用合成故障测试替代 ATE。

当前 [体素边界与静止误配修复](docs/voxel_neighbors_20260916.md) 保留 **2 米根体素、0.2 米降采样**，迭代上限为 **30 次**。相同点云的 17 帧回放由 9 次有效配准增至 17 次，中位处理时间约 56 ms。另已修复[视觉短暂失败后的恢复](docs/visual_recovery_gap_20260916.md)，并通过真实图像遮黑回放；这些不代表在线行驶精度。

此前 [跳变修复与体素对比](docs/jump_repair_20260916.md) 使用 20 次迭代。同一段历史行驶数据 LiDAR 匹配 68/68 帧成功，评分路程 14.10 米，LiDAR 位置 ATE **0.133 米（0.94%）**。2.5 米、3 米根体素未显示优势。该成绩属于历史版本的回放结果，不能直接代替本次算法修改后的行驶验收。

2026-09-16 配准修复：同一段 68 帧在线录制数据按 1 倍速回放，融合位置 ATE 从 **0.358 m 降至 0.178 m**；评分区间约 14.10 m，ATE／路程 **1.26%**。68 帧全部入图、0 丢帧，10 项接口检查通过。LiDAR 后端处理时间中位数约 **98.5 ms**、P95 约 **136.1 ms**。这些是指定数据上的测量，不代表任意地形或高频采集性能。
